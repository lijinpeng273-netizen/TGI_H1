# 把 Terrain Grounded Imagination 迁移到 h1_unitree_official_v1

本文对应 `/home/ljp/human_learn/TGI/terrain-grounded-imagination-main`。目标是让训练、落脚点预测、策略导出和仿真评估都使用这套 **19 自由度、51.649896 kg 的 H1**。下文的现有文件可以点击定位。标有“建议新增”的文件、`--robot h1` 和 `FPM-H1-*` 任务名是实施本方案后才有的接口。

## 先看迁移的终点

TGI 每个控制周期都要完成一个闭环。策略读取骨盆运动、19 个关节的状态以及脚将要踩到的地形，输出 19 个关节的目标角偏移。仿真推进后，世界模型学习“这次动作使机器人怎样运动、哪只脚触地”。随后策略在世界模型里向前推演，用速度跟踪、站姿、足底支撑等回报学习动作。因此，**同一只脚、同一个关节、同一份地形高度，必须在训练和评估中有相同的物理含义**。[仓库工作流](../README.md#L48) · [TGI 训练器](../tgi/src/tgi/training/trainer.py#L71) · [模拟器采集转移](../tgi/src/tgi/env/sim.py#L333)

| 你要运行的流程 | 机器人从哪里进入 | 这次需要接通的部分 |
|---|---|---|
| `fpm/` 基线 | Isaac Lab 注册的任务，默认 PhysX | H1 环境、PPO 行走策略、根据未来触地位置训练的落脚点预测器 |
| `tgi/` 主算法 | 直接构造 FPM 的环境配置，切换 Newton 采样 | 同一套 H1 环境约定、可微运动学、世界模型、想象训练和策略导出 |
| 两种仿真评估 | 同一份导出策略进入 FPM/PhysX 验证或 MuJoCo `sim2sim` | 关节排列、PD、地形观测、初始化高度及跌倒判据 |

**推荐实施顺序**是先让一台虚拟 H1 的参数与足部坐标可验证，再改学习张量，最后接导出和跨引擎验证。TGI 依赖 FPM 包中的环境定义，可以直接训练自己的世界模型、落脚点预测器和策略。完整跑完一次 FPM/PPO 属于独立的基线实验。[FPM 训练入口](../fpm/scripts/train.py#L43) · [TGI 环境入口](../tgi/src/tgi/env/env_cfg.py#L66) · [TGI 训练入口](../tgi/scripts/train.py#L10)

## 第三步　给 PhysX 和 Newton 分别接入校准动力学

**PhysX 入口。** 建议新增 `fpm/src/fpm/assets/h1.py`，参照现有 `G1_CFG` 定义 `H1_CFG`。`spawn.usd_path` 指向校准 USD，开启 `activate_contact_sensors=True`，使用浮动骨盆和第二步的 `init_state`。用 H1 的精确关节名给 `ImplicitActuatorCfg` 设置 `stiffness`、`damping`（控制 Kd）、`effort_limit_sim` 和所选 `velocity_limit_sim`。机械 armature、关节摩擦和被动阻尼应继承已正确读取的资产值，或依据 JSON 显式写到对应的机械属性。若沿用 `soft_joint_pos_limit_factor=0.9`，把它记录为训练用软限位。确认 19 个关节各属于一个 actuator group。[现有 ArticulationCfg 和执行器写法](../fpm/src/fpm/assets/__init__.py#L29) · [PhysX 已有参数读回](../h1_unitree_official_v1/isaacsim_readback.json)

**Newton 入口需要单独处理。** 本包 USD 的逐轴辨识值存在 `physxJointAxis:angular:*` 等属性中。我用仓库 README 指定的 **Newton 1.6.1** 单独运行 `ModelBuilder.add_usd`。直接加载校准 USD 时，刚体和脚部碰撞都能导入，19 个铰链的 `joint_armature`、`joint_friction`、`joint_damping` 却全部为 0。左膝应当依次为 `0.0000714160`、`3.4275337`、`0.00265841`。这会产生一种很难靠观察画面发现的误差，机器人外形正确，世界模型学到的却是另一套动力学。[本包左膝辨识值](../h1_unitree_official_v1/joint_parameters.json#L28) · [Newton 1.6.1 属性映射](https://github.com/newton-physics/newton/blob/v1.6.1/newton/_src/usd/schemas.py#L126)

**建议新增** `tgi/scripts/prepare_h1_newton_usd.py`。下面是可从本仓库根目录运行的转换核心，所用 Python 需能导入 `pxr`。它从校准 USD 派生独立文件，两只脚保留源模型的凸包碰撞。Newton 1.6.1 的此处 USD 角阻尼以“每度”为单位，解析器会再转回“每弧度”，因此写入值要乘 `π/180`。原有 G1 转换脚本负责把碰撞 API 移到 G1 的碰撞几何上。本包 H1 的 20 个碰撞几何已经有该 API。[原 G1 转换脚本](../tgi/scripts/convert_g1_usd.py#L19) · [Newton 1.6.1 阻尼换算](https://github.com/newton-physics/newton/blob/v1.6.1/newton/_src/utils/import_usd.py#L1748)

```python
from pathlib import Path
import json
import math
from pxr import Sdf, Usd, UsdPhysics

assets = Path("h1_unitree_official_v1")
params = json.loads((assets / "joint_parameters.json").read_text())["parameters"]
source = Usd.Stage.Open(str(assets / "h1_unitree_calibrated.usd"))
stage = Usd.Stage.Open(source.Flatten())
seen = set()
for prim in stage.Traverse():
    if prim.IsA(UsdPhysics.RevoluteJoint):
        name = prim.GetName()
        assert name not in seen
        row = params[name]
        values = {
            "newton:armature": row["armature"],
            "newton:friction": row["frictionloss"],
            "newton:damping": row["damping"] * math.pi / 180,
        }
        for key, value in values.items():
            prim.CreateAttribute(key, Sdf.ValueTypeNames.Float).Set(value)
        seen.add(name)

assert seen == set(params) and len(seen) == 19
dst = Path("tgi/src/tgi/assets/h1_unitree_calibrated_newton.usdc")
if not stage.GetRootLayer().Export(str(dst)):
    raise OSError(f"无法导出 Newton 资产 {dst}")
```

**验证位置很重要。** 先用下面的独立读回排除 USD 导入问题。对转换副本，我实测 57 项均通过，三组的最大绝对误差分别约 `3.2e-9`、`2.3e-7`、`1.7e-7`。随后在训练环境完成执行器创建、`reset` 和随机化后，再从实际后端读回这些量一次，并检查力矩限幅、总质量与双脚接触。独立解析只覆盖第一层，后面的 Python 配置仍有机会改写参数。[TGI 环境初始化](../tgi/src/tgi/env/sim.py#L88) · [TGI 现有关节随机化](../tgi/src/tgi/env/sim.py#L193)

```python
# 接上段代码，使用带 USD 导入支持的 Newton 1.6.1 环境
import newton

builder = newton.ModelBuilder()
builder.add_usd(str(dst))
dof = {label.rsplit("/", 1)[-1]: builder.joint_qd_start[i]
       for i, label in enumerate(builder.joint_label)}
for name, row in params.items():
    k = dof[name]
    for field, expected in (("joint_armature", row["armature"]),
                            ("joint_friction", row["frictionloss"]),
                            ("joint_damping", row["damping"])):
        actual = getattr(builder, field)[k]
        assert math.isclose(actual, expected, rel_tol=1e-5, abs_tol=1e-9), (name, field, actual, expected)
```

## 第四步　定义两只脚真正“落在哪里”

H1 的足部碰撞几何挂在 `left_ankle_link` 和 `right_ankle_link` 上，每脚只有一个 pitch 踝关节。MJCF 只有一个名为 `imu` 的 site，位于 `torso_link`。而 TGI 运动学默认查 `left_foot`、`right_foot` 和 G1 的 `*_ankle_roll_link`。本步要同时定义**足底参考点**和**承受接触力的刚体**。[H1 左踝几何](../h1_unitree_official_v1/h1_unitree_calibrated.xml#L72) · [躯干 IMU](../h1_unitree_official_v1/h1_unitree_calibrated.xml#L114) · [TGI 运动学构造器](../tgi/src/tgi/mdp/kinematics.py#L14)

1. **在派生的 FK 模型中加两个无质量 site。** 本包脚网格在踝系的范围约为 `x=[-0.100,0.200] m`、`y=±0.015 m`，最低点 `z=-0.070 m`。取 `(0.050, 0, -0.070) m` 作为足底中心是本指南的几何约定。下面的辅助函数可放到 TGI 的运动学模块，供 `IsaacLocoSim` 和离线 FK 使用。原始 XML 及 SHA256 清单可以继续验证。[足部尺寸与参考资料](../h1_unitree_official_v1/README_ZH.md) · [现有加载位置](../tgi/src/tgi/env/sim.py#L92)
2. **把名字传进现成 FK。** 在 `policy_io.build_mdp` 调用运动学构造器时，传 `site_names=("left_foot","right_foot")`、`body_names=("torso_link","left_ankle_link","right_ankle_link")`。现有类从 MJCF 建链，主要计算可以复用。保留这个返回顺序，因为 `MDP.context` 把刚体第 0 项当躯干、第 1、2 项当左右足部。[FK 调用位置](../tgi/src/tgi/policy_io.py#L39) · [按索引消费 FK 的位置](../tgi/src/tgi/mdp/mdp.py#L123)
3. **给 FPM/PhysX 同样的足底坐标。** `system_pose.feet_pose_w` 和 `feet_pos_b` 当前读刚体原点。为 H1 增加带局部偏移的观测函数，先算 `p_sole_w = p_ankle_w + R_ankle_w @ offset`，再用骨盆逆变换得到 `p_sole_b`。两项输出仍按左、右排列，足部朝向沿用踝刚体朝向。`system_contact` 和 TGI 的 `foot_contact` 则分别从各自传感器按左右踝刚体名查 ID。这样 FPM 学的“未来接触点”、想象中计算支撑的位置、评估时的真值指向同一点。[FPM 位姿观测组](../fpm/src/fpm/tasks/locomotion/config/g1/env_cfg.py#L137) · [世界系与骨盆系观测](../fpm/src/fpm/tasks/locomotion/mdp/observations.py#L165) · [TGI 接触读取](../tgi/src/tgi/env/sim.py#L228)

```python
import mujoco

def build_h1_fk_model(xml_path):
    spec = mujoco.MjSpec.from_file(str(xml_path))
    for side in ("left", "right"):
        ankle = spec.body(f"{side}_ankle_link")
        ankle.add_site(name=f"{side}_foot", pos=[0.05, 0, -0.07], size=[0.002, 0, 0])
```

**单独修正 MuJoCo 射线分组。** 原 `TERRAIN_GROUP=2` 正好是官方 H1 的**视觉网格组**，碰撞网格在组 3。将原逻辑套到 H1 时，我在水平地面用从 z=10 m 向下的同样射线测得，骨盆投影 `(0,0)` 读到躯干 **1.72505 m**，左足附近 `(0.08947,0.20286)` 读到左肘 **1.09905 m**。策略会把自己的身体当成地形。这个包的机器人没有使用 geom group 5，建议把地面、`box` 生成的障碍和单独创建的斜坡统一放到 **5**，射线掩码只开 `gg[5]`。在相同姿态下，两处正确读数均为 **0.00000 m**。再测一个平台顶面，读数应等于该平台的已知高度。[H1 的 visual/collision 分组](../h1_unitree_official_v1/h1_unitree_calibrated.xml#L8) · [地形创建](../tgi/scripts/sim2sim.py#L29) · [射线查询](../tgi/scripts/sim2sim.py#L114)

下面的平地测试可直接在现有资产上运行。它用同一模型、同一姿态测试修正后的掩码，便于以后更换 H1 模型时回归。

```python
from pathlib import Path
import mujoco
import numpy as np

scene = Path("h1_unitree_official_v1/scene_calibrated.xml")
m = mujoco.MjModel.from_xml_path(str(scene))
d = mujoco.MjData(m)
mujoco.mj_resetDataKeyframe(m, d, m.key("home").id)
mujoco.mj_forward(m, d)
terrain_group = 5
assert not np.any((m.geom_bodyid != 0) & (m.geom_group == terrain_group))
floor = m.geom("floor").id
m.geom_group[floor] = terrain_group
mask = np.zeros(6, dtype=np.uint8)
mask[terrain_group] = 1
for x, y in [(0, 0), (0.08947, 0.20286)]:
    hit = np.array([-1], dtype=np.int32)
    dist = mujoco.mj_ray(m, d, [x, y, 10.0], [0, 0, -1.0], mask, 1, -1, hit)
    assert hit[0] == floor and abs(10.0 - dist) < 1e-6
```

## 第九步　在训练机上按这个顺序验收

资产包原报告使用 Isaac Sim 5.1 / Isaac Lab 2.3 的 PhysX，当前 TGI README 给出的组合是 Isaac Lab 3.0、Isaac Sim 6.1 和 Newton 1.6.1。本次完成了校验和、MuJoCo 编译与足底 FK/射线检查、OpenUSD 检查和 Newton 1.6.1 独立 CPU 导入。派生 USD 的 Newton 模型最终有 20 个刚体，质量和为 **51.649895 kg**（float32）。完整 Isaac Lab 场景中的运行时读回、策略训练、行走评估和实机表现仍需在对应环境验证。[仓库版本](../README.md#L53) · [包内验证条件](../h1_unitree_official_v1/README_ZH.md)

| 顺序 | 实际做什么 | 通过的依据 |
|---|---|---|
| 1. 资产和驱动 | 在资产目录执行 `sha256sum -c SHA256SUMS`。按第三步导出并读回 Newton 资产，在 Isaac 创建一个固定参数 H1，核对名义质量、19 组 Kp/Kd/力矩上限和 57 个被动参数 | 顺序按名对上，浮动基座为 6 个自由度，左、右脚都有碰撞体。定基/悬空做单轴小幅目标回放，可和包内留出轨迹比较 |
| 2. 坐标与观测 | 固定地面、关噪声，用 `home` 及带骨盆旋转的姿态做 FK。站定、单脚摆动、移动到台阶边，分别检查 site、两个接触通道、足底支撑比例及射线 | 平地高度为零，左右脚标签正确。站稳后双足竖向支撑力之和的时间均值应与 `mg≈507 N` 同量级。落地瞬间峰值另算 |
| 3. 学习链路 | 跑一次 FPM-H1 的短 PPO 更新验证任务注册、观测、镜像。TGI 另跑一次跨过世界模型预热、FPM 启用和想象策略更新的短训练，检查有效标签数、预测输出和损失 | 能写 H1 快照，各项损失为有限值，左右脚都有实际离地→触地样本，激活 FPM 后预测可随状态改变。短训练用于检查接口，步态质量另行评估 |
| 4. 导出一致性 | 从同一帧保存 `q,dq,base_pose,cmd,a_prev` 和同一份地形，关噪声与漂移。先比 FPM 的 50 项和 4 个输出，再比 69 项本体、102 项扫描、19 个动作和最终目标角 | PyTorch 与 ONNX 可先按最大绝对差 `1e-4`（FP32 参考）检查。不同则先定位第一个不一致的观测块，最后比较按名字重排后的 PD 目标 |
| 5. 步态与跨引擎 | 在足够训练的 H1 策略上依次做零速站立、直行、转弯、走后停、台阶与踏脚石。再开延迟、噪声及选定随机化。用相同策略、种子、命令和 PD 在 nominal / calibrated 上分别测试 | 同时记录存活、速度误差、落脚误差、足滑、力矩饱和率和地形通过率。MuJoCo 的不同动力学用同样的几何和参考点，PhysX 验证明确使用 H1 任务，可据此判断差异出在哪一层 |
